# U1 验收清单：「自己用它干一天活」

> 2026-11-03 · `cmd/app/main.go`（约 1000 行）· Viva 原生窗口
>
> **U1 的唯一验收标准不是截图好看、不是测试全绿，是「自己用它干一天活」。** 这份清单把它拆成能当场做的动作。
>
> 数字分两栏：**实测**＝本机跑过、有出处；**预期**＝按已实测的规律推算、还没在这条路径上验过。

## 怎么起

```bash
# 终端 1：带真实会话 + 真模型
mockd -sessions "D:/DeepSeek Harness/home/sessions" \
      -acp "D:/DeepSeek Harness/default-workspace/DSH-GO/dshd.exe" \
      -acp-manifest "D:/DeepSeek Harness/default-workspace/dsh-ui/tmp/dsh-acp.toml"
#   注意：含空格的路径必须自己加引号（PowerShell 的 Start-Process -ArgumentList 不会加）

# 终端 2：界面
dshui                 # 默认 -addr http://127.0.0.1:7788 -tail 40
dshui -demo           # 额外插一条工具卡 + 一个审批气泡，用来验渲染
```

`dshui` 的全部开关：`-addr` `-session` `-tail` `-limit` `-smoke` `-demo`。

## 一、启动与连接（7 条）

| # | 动作 | 期望 | 怎么判 |
|---|---|---|---|
| 1.1 | 双击 `dshui.exe`，掐秒表到窗口出现 | 窗口出现，左栏有会话，右栏自动打开第一个 | **实测 698 ms**（mockd 带 180 个真实会话在跑）；冷启到窗口 ≤ 1.5 s |
| 1.2 | 不启 mockd，直接开 `dshui` | 不崩、不白屏，状态行说清连不上 | 窗口正常画出；一行红字/状态文字里含 `refused` 或 `connect`；进程不退出、CPU 不烧 |
| 1.3 | `dshui -session 不存在的id` | 报错但不崩，左栏仍可用 | 顶部一行「加载失败: not_found: 会话不存在: …」且**带下一步提示**（`先调 session.list 拿一个真实 id`）；点左栏任一条能正常打开 |
| 1.4 | `dshui -tail 0` | 不崩；要么全拉要么给下限 | 窗口出现、右栏有内容或明确空白提示；**不能**出现 panic / 白屏 |
| 1.5 | `dshui -tail 1000` | 能开，但内存明显上去 | 窗口能开；任务管理器看内存 **> 150 MB**（实测 200 条 = 172.9 MB，1000 条按 0.46 MB/条约 540 MB 是**预期**，不保证能用） |
| 1.6 | 把窗口拖到 700×520（MinWidth/MinHeight） | 不塌、不重叠 | 左栏与右栏都还在；输入框可见；**不出现** 0 高度或文字叠字 |
| 1.7 | 关窗口，进程退出干净 | 无残留进程 | `Get-Process dshui` 为空；`mockd` 与 `dshd` 还在（那是我起的） |

## 二、会话切换（7 条）

| # | 动作 | 期望 | 怎么判 |
|---|---|---|---|
| 2.1 | 打开会话 A，滚到中间，切到 B，再切回 A | 回到 A 的**同一个位置** | 回到 A 时视口里是同几条消息（记下 A 中间某条的序号，切回来它还在屏上） |
| 2.2 | 连点 3 个不同会话（间隔 < 300 ms） | 最终停在最后点的那个，不闪 | 右栏最终是最后点的会话；标题栏与左栏高亮一致 |
| 2.3 | 切到第 6 个没打开过的会话，再切回第 1 个 | 第 1 个不重新拉（温缓存命中） | 切回第 1 个时**立刻有内容**（无加载闪烁）；缓存上限 `cacheLimit = 5`，第 6 个会挤掉最早的 |
| 2.4 | 切到一个 400+ 条的长会话（如 `DSH-GO` 那个） | 只显示最后 `tail` 条，标题写总数 | 标题形如 `<cwd> · 40 条（总 462）`；不是 `会话 session-xxxx` |
| 2.5 | 检查左栏标题 | 有信息量 | 每条都是 cwd 最后一段（`DSH-GO` / `长期记忆系统` / `GOkifu上下文压缩`）；**没有**一条是「会话 session-」开头 |
| 2.6 | 左栏滚到底 | 180 条都在，滚动不卡 | 能滚到最末一条；滚动时 CPU 不高（任务管理器里 < 5%） |
| 2.7 | 切会话时看内存 | 不随切换增长 | 连续切 6 个会话后，内存**不比切换前多 20 MB 以上**（文档树在 `openSession` 里会清空，实测清空前后 172.3 vs 172.9，属噪声） |

## 三、消息渲染（8 条）

| # | 动作 | 期望 | 怎么判 |
|---|---|---|---|
| 3.1 | 打开含完整 Markdown 的会话 | 标题/粗体/斜体/行内代码/链接/列表/引用/代码块/表格**全对** | 逐项目视：`###` 变大变粗；`**x**` 粗；`` `x` `` 有底色；列表有 `•`；引用有左竖线；``` 代码块等宽带圆角；表格有表头加粗 + 行线 |
| 3.2 | 找一条「全是大段 AGENTS.md」的超长消息 | 不被截断（虚拟化盒子给足高度） | 滚到那条，**末尾的文字能看到**；如果被截，说明 `estimateMsgHeight` 低估，记下来 |
| 3.3 | 找含 60+ 字符单行代码块的消息 | **折行**（不是硬切） | ~~这条原本写「会失败」，是误判~~——实测 129 字符单行代码**本来就折行**，内容不丢（2026-11-03 纠正）。代价是折行处代码列对不齐，见 `docs/u1-codeblock.md` |
| 3.4 | 找一条空正文的消息（`tool` 之外的） | 不塌、不报错 | 那一条渲染成一个矮卡片，间距正常，后面的消息不上移重叠 |
| 3.5 | 纯 ASCII 消息 | 字体正常 | 不带中文字体回退的怪异间距；等宽块对齐 |
| 3.6 | 含 emoji 的消息（😀 🎉 🇨🇳） | 彩色 emoji 正常，国旗降级为 `CN` | 彩色 emoji 有颜色；`🇨🇳` 显示成 `CN` 两个字母是 **Windows 系统限制**（Electron 里同样），不是 bug |
| 3.7 | 表格消息 | 列对齐、表头加粗 | 每行每列不串位；中文与英文混排时列宽合理 |
| 3.8 | 嵌套引用（`> >`） | 两层竖线或至少不丑 | 允许只有一层竖线（Viva 的 markdown 包对嵌套引用的处理没细验），但**不许**渲染成普通段落 |

## 四、流式（7 条）

| # | 动作 | 期望 | 怎么判 |
|---|---|---|---|
| 4.1 | 在会话里发「慢慢数到三」 | 字**一个一个**出现 | 气泡里文字逐字增长（约 60 ms/字）；有 `Spinner`；不是一次性蹦出整段 |
| 4.2 | 等回答结束 | `done` 落条，气泡变成正式消息 | 流式气泡消失；消息列表多一条「助手」；标题里的条数 +1 |
| 4.3 | 流到一半切到别的会话，再切回来 | 不丢、不乱 | 切回来时那条回答**要么还在流、要么已经落条**；不会出现半截卡住不动 |
| 4.4 | 流到一半关窗口 | 进程退出，不崩 | 无 panic 输出；`mockd` 侧那条流会自己超时收尾（不断言） |
| 4.5 | 发一条会调工具的问题（如「列一下当前目录」） | 先出工具卡，再出文字 | 气泡顺序：`[工具] bash` → 文字；工具卡的 `Args` 是一行命令 |
| 4.6 | 连发两条（第一条没答完就发第二条） | 第二条被拒或排队，不串 | 状态行给 `busy`；不出现两条回答混在一个气泡里 |
| 4.7 | 发中文 + emoji + 换行 | 原样送出去 | 气泡里内容与输入一致；换行保留 |

## 五、工具与审批（6 条）

| # | 动作 | 期望 | 怎么判 |
|---|---|---|---|
| 5.1 | `dshui -demo` 打开 | 底部两条工具卡 | `bash · git status --short · exit 0 · 3 files changed` 与 `read · internal/apiclient/mux.go · 1.2 KB`；灰底圆角，**不套「助手」标签** |
| 5.2 | 同上，看审批气泡 | 先命令、后自述，且自述标「不可信」 | 顺序是：`需要审批` + 工具名 → **命令原文** → `模型自述（不可信）：…` → `[拒绝] [允许]` |
| 5.3 | 点「允许」 | 气泡消失，状态行说已允许 | 气泡没了；状态行一行「已允许」；**不**误触发发送 |
| 5.4 | 点「拒绝」 | 气泡消失，状态行说已拒绝 | 同上，文字是「已拒绝」 |
| 5.5 | 真模型触发审批（问一个要 `bash` 的问题） | 气泡出现，命令**完整不截断** | 长命令要能看全（哪怕换行）；拒绝后面板不崩 |
| 5.6 | 审批气泡出现时窗口变窄到 760 | 按钮不被挤出 | `[拒绝] [允许]` 两个都在视野内 |

## 六、长会话与内存（7 条）

| # | 动作 | 期望 | 怎么判 |
|---|---|---|---|
| 6.1 | 打开最长的会话，`-tail 200` | 能开，但内存高 | **实测 172.9 MB**（442 条里渲染 200 条时）；CPU 峰值 4.16 s |
| 6.2 | 同上，默认 `-tail 40` | 明显降下来 | **实测 72.5–75.5 MB**；CPU 0.31 s 且之后不涨 |
| 6.3 | 在长会话里慢慢往上滚 | **上方内容不闪、位置不跳** | 逐格滚动时，视口里已有内容**不重排**；估算高度是固定盒子（`docs/virt.md` 的原理） |
| 6.4 | 快速甩滚轮（一次滚 10 屏） | 允许短暂空白，但停下来就好 | 停下后 1 s 内内容全部画出来；**不出现**内容错位或重复 |
| 6.5 | 滚到最底部 | 稳稳停在最后一条 | 最后一条完整可见，不被输入框压住（`MinHeight(160)` 保底） |
| 6.6 | 滚到底后发一条新消息 | 跟随到底 | 新消息出现后视口仍在底部（滚动区 `Follow(true)`） |
| 6.7 | 长时间挂着不操作（5 分钟） | CPU 趋近 0，内存不涨 | 任务管理器：CPU 累计增量 < 1 s；内存与 5 分钟前差 < 5 MB |

## 已知不能做的（不是 bug）

| # | 做不到的 | 为什么 / 什么时候能好 |
|---|---|---|
| K1 | **续会话用的是副本** | `mockd` 把真实会话复制进 `tmp/dshd-home` 再 resume。**每次点开同一个会话都会重新复制**，上次聊的内容不会带过来。要真续，得 U0（`internal/transport`）直连真宿主，那时 home 只有一个 |
| K2 | **`mockd` 是过渡管，不是终局** | 它把 ACP 的 update 翻译成 `/api/mux` 帧。终局是宿主直接吐 v4 原始事件，不经 ACP 绕路（`UIPLAN.md` 的 U0） |
| K3 | ~~没有搜索 / 过滤~~ **已补**（2026-11-03 09:20） | 侧栏顶部有过滤框，按标题 + cwd 实时匹配。注意它是**内存里线性过滤**，不是索引——182 条够快，上千条要换做法 |
| K4 | **没有侧栏折叠** | 左栏固定宽度。折叠是纯 UI 改动，但会牵动虚拟化的宽度估算（`estimateMsgHeight` 按固定宽度算），要一起改 |
| K5 | **没有多窗口** | 一个进程一个窗口。多窗口要么多进程（每窗 80 MB 基线），要么一个进程多 View（Viva 的 `app.Config` 现在是单 Tree） |
| K6 | 代码块横向滚动**接了一半** | `internal/mdlite/overflow.go` 的容器已接进 `cmd/app`（见 `docs/u1-codeblock.md`），但**只有 `-demo` 注入的样例验过**；滚轮/拖拽交互还没接 |
| K7 | **老消息降级成纯文本** | `markdownBudget = 30`：只有最近 30 条走 `MarkdownView`，更早的用 `f.Wrap`。原因是全上 Markdown 时 200 条要 168.8 MB / 首排 4 s（实测）。这是**有意取舍**，不是漏做 |
| K8 | **没有语法高亮** | Viva 的 `MarkdownStyle.Highlight` 是留给调用方的钩子，我们没填。填了能让代码块有颜色，但要对每种语言写一遍 lexer |
| K9 | **斜体看起来像加粗** | Viva 官方承认：比例字体还没有 italic face，斜体暂时画成更重一档（`docs/viva-scroll-and-text.md` 记了） |

## 一天怎么用（建议路径）

1. 早上起来，`dshui` 打开最近那个会话 → 看昨天到哪了（验 2.4 2.5）
2. 接着聊两句真事（验 4.1 4.2 5.5）
3. 中途翻到另一个老会话对一下结论，再翻回来（验 2.1 2.3）
4. 下午在长会话里翻半小时历史（验 6.3 6.4 6.5）
5. 下班前看一眼任务管理器（验 6.7）

**这一天里任何一步让你想「算了还是开 DSH 吧」，那就是 bug，记下来。**
