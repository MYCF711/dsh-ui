## 一、最贵的四个（各花了好几轮才查出来）

### 1. 假红：测试抢固定端口（花 5+ 轮）

**症状**：`go test ./internal/apiclient/` 突然变红，`TestMuxLive` 超时收不到 gap。改逻辑、加日志、回退代码，全没用。

**真因**：我自己起的 `mockd-dbg.exe` 占着测试写死的 **7788** 端口。测试连到了那个实例，而它的"跳号"是包级一次性的、已被前一次订阅消耗光——所以永远等不到 gap。

**怎么确认**：`powershell -Command "(Get-NetTCPConnection -LocalPort 7788).Count"`，或者看测试日志里的 mockd 输出是不是"早就启动过了"。

**已根治**：mockd 默认 `-addr 127.0.0.1:0`，测试从日志读真实地址。**但记住这个教训**：测试夹具里任何写死的资源（端口、路径、文件名）都会在并行时咬人。

### 2. 假数据被当成真厂商行为（花 3 轮）

**症状**：界面按 `allow-once`（连字符）发审批，怀疑宿主契约不一致。

**真因**：连字符是**我写的 mockd 假数据**。宿主真机报的是 `optionId 必须是 allow_once / allow_always / reject_once 之一`——**下划线**。

**怎么确认**：向真宿主发一个错的 optionId，看它的错误提示；**不要从 mockd 或文档推断宿主行为**。

**已根治**：界面按 `kind` 匹配而不是按 id 字面量，所以两种写法都能对上。

### 3. 对面根本不推帧，我却在客户端找（花 3 轮）

**症状**：切回会话时 `since=0`（等于从头重放），我以为是界面水位没记上。

**真因**：宿主 `FrameSub` 的重放条件是 `sinceSeq > 0`，而界面**首次**订阅是 `sinceSeq=0` → **一条帧都不推**。客户端表现是"像卡住" + 水位永远是 0。

**怎么确认**：在客户端加一行 `log.Printf` 打在 `applyEvent` 上——**一条都没打出来**，说明不是水位问题，是根本没收到。

**教训**：**"客户端看起来的低效"可能整条链路的起点就在对面**。查之前先确认对面到底推了什么。

**已修（未提交，见 `docs/patches/`）**：`sinceSeq >= 0` 也重放。

### 4. curl 场景的审批必然超时（花 2 轮）

**症状**：脚本里模型调了工具，但审批永远走不通，会话里留下 `Error: 用户拒绝了 bash 提示`。

**真因**：`approval/request` 是走 **WS** 推给客户端的。只用 curl 发 prompt 就没有 WS 订阅者 → 没人应答 → 宿主 **120 秒后默认拒绝**。

**怎么确认**：会话尾部会留下"用户拒绝了"，同时宿主日志里**没有**任何 approve 记录。

**这不是 bug，是架构约束**：无人值守 + 无客户端时 `policy=ask` 必然走向拒绝。验审批必须让**界面**（WS 客户端）在场。

## 二、编码类（一次就够，但很难自己发现）

### 5. Git Bash 调原生 curl，中文 argv 走 CP936

**症状**：发出去的中文 prompt 落进会话变 `\xd6\xbb` + `U+FFFD`，模型自己都说 "The message is mojibake encoded"。

**避免**：prompt 走文件（`-d @file` 或 `--data-binary @file`），或者用 Python `urllib`。脚本 `scripts/e2e-workday.sh` 就是这么做的。

### 6. `GetWindowRect` 在最小化窗口上返回 160×28

**症状**：`-shot` 偶尔产出 895 字节的废图，内容是半个标题栏。

**真因**：抓图时窗口处于最小化。4 张历史废图 **md5 完全相同**就是线索——同一个物理状态。

**已修**：`captureWindow` 先 `IsIconic` → `SW_RESTORE`，再用 760×520 卡一道，不达标明确失败（不再静默存废图）。

## 三、Go / 工具链类

### 7. `defer` 顺序反了 → goroutine 泄漏 40 秒

**症状**：对端断开后 channel **40.01 秒**才关（= 2× 心跳间隔），goroutine + ticker 一起漏。

**真因**：`defer stopPing()` 写在 `defer pingWG.Wait()` 之前。LIFO 下先 Wait 后 stop，ping goroutine 卡在 `conn.Write` 上，Wait 永远等不到。

**正解**：`defer func(){ stopPing(); pingWG.Wait() }()`。

### 8. `log` 默认写 stderr，不是 stdout

**症状**：想从子进程的 stdout 读它打印的监听地址，读不到。

**避免**：拿不到日志时先试 stderr。`cmd.Stderr = io.MultiWriter(os.Stderr, pw)`。

### 9. seq=0 的控制帧会把水位归零

**症状**：`seq 1 → 5`（中间缺 2/3/4）却报 **0 个 gap**。

**真因**：`last = f.Seq` 无条件赋值，一个 error 帧（seq=0）就把水位打成 0，`last != 0` 那道断号检测的门就此关掉。

**正解**：`f.Seq <= 0` 的帧不进水位。

### 10. 断号后 `break` 重连 = 无限循环

**症状**：日志 4 秒内重连三次，永远收不到后续内容。

**真因**：收到 gap 就 break 出去带水位重订，但水位没变 → 宿主从同一位置推同样的东西 → 又报同样的 gap。

**正解**：断号只**上报**，补洞走 `session.history`（只补缺失区间）。断号与重连是两件事。

## 四、协作类

### 11. 别按镜像名 kill 进程

多个代理并行时 `taskkill /IM dshd-serve.exe` 会误伤别人的实例（子代理实测到自己的宿主被外部终止）。**只按核对过的 PID kill**。

### 11b. 同一个 READY 包可能被两个会话同时派出

**症状**：V2 报告 `plugins/dssidebar/` 里"还有另一个 V2 在并发写，20:31 覆盖了 sidebar.go"；V3 报告 `plugins/dscomposer/composer_test.go` 在它写完后 11 秒出现、按另一套数值断言。

**真因**：这仓是**多会话共享**的。别的会话（另一个 Lead）也在按同一份 `UIPLAN.md` 派单表派活，而派单表里的状态回填是**每个会话各自的**——我这边标了 IN_PROGRESS，它那边没看见。

**怎么发现**：子代理主动报告"同一目录有另一个 agent 在写"。这是我**唯一**的信息来源——跨会话之间没有通信通道，`send_message` 对 subagent 也无效（只对 teammate 有效）。

**避免**：
1. 派单前先 `git status` 看目标目录有没有别人刚动过的痕迹（mtime 在几分钟内、untracked 新文件）
2. 派单时在任务书里写死："**如果发现目录里有你没写过的文件，先报告，不要覆盖**"
3. 冲突发生后：让子代理**保留双方较好的部分 + 把差异写成对照表**，由 Lead 裁定；**不许为了变绿放宽断言**
4. 裁定依据优先级：**有出处的官方规格 > 实现现状 > 无出处的测试断言**

### 12. 宿主仓 commit 需要授权

`AGENTS.md` §4：commit/PR/push 由任务书显式授权，两仓 push 都要用户当次确认。所以宿主改动只做 patch 备份（`docs/patches/`），不自行提交。
